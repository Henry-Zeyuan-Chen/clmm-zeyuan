## Implementation and prospective protocol

`StreamingReplay` and `SleepSession` accept `freshness="literal"` (default) or `freshness="bounded"` for continuous/periodic replay. At application time, after the real arrival updates the FIFO, bounded replay uses the current FIFO record for the sampled key if present. If evicted, it uses the original frozen record. The original four samples and RNG are unchanged. Extras never refresh the FIFO, no writes are discarded, and no full-history version map, revision flags or query answers are available to the policy. Literal exports/events retain v1 compatibility; bounded exports use v2 with explicit freshness and combined-session coherence checks.

All four replay conditions share candidate draws, sampled-key order, real arrivals, weights, route table, FIFO8, snapshot4, 64KiB adaptive traces and write opportunities. Actual bounded source/value content can differ between schedules because the latest observed value differs at their application times.
