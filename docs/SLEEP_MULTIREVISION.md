## Results

Periodic replay underperforms continuous replay on the two declared D128 endpoints. Both replay schedules underperform the equal-write repeat-current control. All twelve checkpoints pass common short and neutral K16 acquisition, with 100% neutral six-target all-correct. The replay schedules themselves damage replacement before the final distractor tail: every continuous and periodic arm/phase fails its own 80% D0 all-six-correct gate. These are revision/interference comparisons; keep all conditions and do not describe the curves as an admitted-retention experiment.

| Repeat current | 84.88% | 93.89% | 384 |
| Continuous | 83.31% | 84.22% | 384 |
| Periodic | 83.08% | 81.76% | 384 |

These means equally weight content and the mean of all five random maps, then average both fixed parents and phases. These conditional intervals support a difference for this fixed-model protocol. The stable effect is small; the random-family stable-only descriptive interval crosses zero. Revised timing differences are negative in both routing families.

Secondary D128 comparisons to repeat-current are also negative: continuous revised −9.6680 points, nominal 95% [−12.3145, −7.2461]; periodic revised −12.1289, [−15.1082, −9.3555]. Stable differences are −1.5723 and −1.8018 points. Online is a lower-write anchor, while repeat is the relevant equal-write control. Neither reference replay policy helps on this task.

D0 revised accuracy is 100% online/repeat, 71.48% continuous and 60.94% periodic. Continuous all-six-correct ranges 32.03–58.59% across the 24 model/phase conditions, periodic 28.13–32.03%; online/repeat range 89.06–97.66% and pass all 24 conditions each. Revised replay accuracy improves by D64 and then falls by D128; a monotone forgetting interpretation would miss this recovery from initial replacement damage.

Every stream's continuous/periodic extra `(source,key,value)` sequence matches exactly. Across the same 128 worlds, phase0 has 336 stale extra applications under continuous and 385 under periodic; phase2 has 156 versus 385. Counts are unchanged by the final tail, because genuine changes precede it. Final-obsolete-query sample counts are identical between arms. This demonstrates changed application-time validity from the timing intervention. It does not by itself prove that stale writes mediate every accuracy difference: interference and ordering also change.

Each fresh world has sixteen initial facts and six queried targets: two early stable facts, two initially replay-eligible stable facts and two revised facts. Each revised key undergoes three genuine changes, with no value cycling. Six current query values remain distinct after each change. Two placements within four-arrival blocks and final tails of 0, 64 or 128 arrivals form six paired pressure cells. Sixteen distractors separate revision rounds. Tail zero still contains the complete revision/interference sequence; it is not a neutral acquisition test.

Continuous and periodic replay use the same eight-record latest-per-key FIFO and four frozen samples per block. They consume identical observed histories, literal `(source,key,value)` samples in exactly the same order and equal extra writes. Continuous applies one sample after each arrival; periodic applies all four after the fourth arrival. A sample can become obsolete between sampling and application. Such stale writes are measured, not filtered using future answers. Repeat-current matches the write count with different content; online has no extra writes and is a lower-budget anchor. All arms use the same 64 KiB functional trace state per stream. Equal writes do not imply equal FLOPs.

The main split has 128 fresh paired world histories, seed 91123, excluding both actual training streams and prior saved numeric KV histories. Data, excluded signatures, checkpoints, full source snapshots and SHA hashes are frozen in the packet. Six query targets are evaluated separately from the recent distractor. Early stable facts never enter the eight-record replay window, so their results measure indirect interference rather than direct rehearsal.

## Reuse the shared baseline

The packet's `models.json` lists all twelve exact checkpoint hashes, slow hashes, routing tables and original training metadata. Load with `scripts.revision_local_experiment.load_checkpoint(path, torch.device(...))`; its return values are the model and payload. Freeze/evaluate the slow model, then construct `clmm.sleep.SleepSession` for functional memory writes. `prime` consumes common online-only prefill, `observe` consumes a real arrival and its scheduled extra writes, `read` accepts keys only, and `export_state`/`from_state` pause and resume the combined fast memory and bounded replay controller. Pair a saved session with its exact slow checkpoint SHA, because the configuration fingerprint alone does not identify trained weights.

To rerun one full checkpoint evaluation, create a clean detached worktree at the executable commit above, then run `python scripts/sleep_multirevision_experiment.py evaluate --packet <artifact-root>/packet --out <new-output-folder> --model 90511-content-local_delta --max-seconds 1200`. The runner verifies the prepared Git revision and source bytes; a later documentation commit deliberately needs the isolated executable checkout. Do not overwrite any recorded case folder. The recovery package contains the data, exclusions and source needed to relocate this command.

The main packet is an evaluation split, not a training curriculum. These histories become consulted development data after this analysis. New policy tuning needs a fresh declared split. Family-level content/random performance differences include separately learned representations; only the replay timing comparison within the same checkpoint holds those representations fixed.
