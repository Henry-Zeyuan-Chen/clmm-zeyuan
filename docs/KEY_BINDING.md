# Fixed-size key binding diagnostic

Status: implementation and prospective review complete; preparation/experiments pending, November 15, 2026. Branch `sequence-key-binding`. The existing 839,248-parameter byte model stays unchanged. The preceding [sequence freshness study](SEQUENCE_FRESHNESS.md) showed access to present values but almost no requested-key selection. This study isolates an input representation change before scaling or retention work.

The comparison uses the original language parents 68101/68105, independently adapted under two key encodings. Digits retain each three-character numeric key. Atomic replaces that visible three-byte field with one fixed alias byte and two spaces, preserving all other input bytes, record/query positions, lengths and answer labels. The aliases are a fixed random permutation of bytes 128–255. Both arms share 96 original training keys and 32 disjoint dev keys, sampled semantic worlds and exact initial tensors. No tokenizer, vocabulary, head or model parameter is added. This is an encoding-bundle contrast, including changed token identities and prior exposure; it cannot identify segmentation alone as the cause.

All four terminal conditions train at attention segment 128, where both original facts fit in attention. Each receives 2,000 AdamW updates, 32,000 supervised answer forks and 2,908,928 input bytes. The common curriculum has 256 single-fact and 1,744 two-fact updates, eight contexts/two answer forks per update. Single-fact queries are duplicated for equal fork count. Inputs are 63 or 95 bytes; NPZ padding is sliced before forward. No revisions/replay are trained here. This common smaller key pool and acquisition-only recipe differ from the previous study in both new arms; an old-versus-new gain would not isolate encoding.

Evaluation has 256 fresh training-key and 256 dev-key base worlds, exact value-swapped counterparts, and dev wording clones using jointly held-out fact/query templates. Both questions share wording except key; target values differ. Previous inspected history signatures, all actual new training histories, and smoke/engineering histories are excluded, jointly rejecting originals and swaps. The frozen codec, raw prefixes, labels, source and data hashes are stored before GPU evaluation. Atomic bytes are passed directly as uint8/int64, never through UTF8 conversion. Task-unadapted language parents are initial controls, not fully untrained networks.

The two primary endpoints are atomic-minus-digits joint-four correctness (both original and value-swapped question pairs entirely correct), on train-seen and dev-heldout worlds. Whole-world paired bootstrap intervals average the two fixed parents before 5,000 PCG64 resamples, seed 91404; two 97.5% intervals implement the Bonferroni adjustment. They estimate fixed-model history uncertainty. Admission separately requires at least 205/256 both-correct on each of six normal original/swapped groups for a checkpoint. All four terminal checkpoints are retained. Terminal step 2000 is primary; midpoint 1000 is recovery-only.

Normal, segment reset and retrieval-zero controls each forward the complete model. Segment reset is a parity check because 95 < 128; equality is not memory-independence evidence. Retrieval zero uses the existing eval-only wrapper, preserves memory writes and changes downstream activations; it is not a separately trained attention-only baseline. Query-only train/dev probes expose prior answer biases. Report full-256 predictions, both/joint correctness, per-rank accuracy, prediction changes, present-value rate, NLL, legal mass and control contrasts. Each initial/terminal condition saves 10,240 answer distributions; all eight conditions total 81,920.

Compute bound: one 45-minute A6000 allocation, four CPU cores and 16 GiB, no renewal or helper-selection change. Two 20-step/N16 engineering runs check both encodings; only runtime, resources, finite values, reload and source/data validity govern continuation.
